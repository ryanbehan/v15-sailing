This log captures key decisions made during the project, including rationale and timestamps. It helps maintain context for future reference and AI-assisted development.

- **[2026-11-24 — citable sections and final SEO checks]**: Use pinned rehype-slug 6.0.0 (2023-08-31) for Markdown heading IDs and a shared native SectionHeading for JSX headings. Prefix generated IDs with section-; retain existing semantic heading levels and styles. Require nonempty, unique published h2/h3 IDs during export inspection, then derive Markdown section links from the actual HTML IDs rather than guessing slugs. Keep original D2 fences byte-for-byte and source/archival/fleet caveats; use callback replacement when inserting navigation so heading text containing dollar substitutions is not interpreted. Prioritize the homepage hero and defer below-fold image loading/decoding, retaining known logo dimensions and existing fixed photo slots/crops instead of inventing intrinsic dimensions or introducing a separate image pipeline. Use the lowercase fetchpriority HTML attribute for React 18 compatibility. Add real browser fragment-navigation/overflow checks at 375 and 1440 pixels and inspect screenshots. Security/data-flow/project-summary records describe the existing public-content trust and service-auth boundaries; no runtime AI service or training-policy change is introduced. Align CI to Node 22 because Wrangler declares >=22.12, use read-only/nonpersisted checkout credentials and Makefile targets, preserve the legacy dispatch event and add manual execution. Reuse the same edge contract tests for actual public HTTPS/HTTP requests after publication instead of spoofing Host headers over a remote connection. Local transport tests remain real Workers-runtime checks; live/CI execution is a separate post-publication proof, and no Cloudflare webhook is configured by this change.

- **[2026-11-24 — canonical routing and representation delivery]**: Keep the existing Worker/ASSETS architecture and use the shared SEO origin for permanent HTTPS/www canonicalization. Negotiate Markdown with pinned Negotiator 1.1.0 (released 2026-08-20), not an ad hoc Accept parser or crawler identity. Read generated Markdown through its own asset URL, preserve ETags/HEAD/conditional requests, and add Vary: Accept. Direct Markdown and llms.txt are noindex but retrievable; negotiated canonical production URLs remain indexable. Preview/search/admin/error responses receive HTTP noindex protection, and missing assets serve the real 404 export with 404 status. Add pinned Wrangler 4.164.0 (released 2026-11-17) for local real-runtime tests. Disable local route-origin inference, which otherwise masks host boundaries. Wrangler also rewrites same-host Location headers regardless of URL scheme; keep the apex HTTP-upgrade guard at the direct Worker API boundary with native Request/Response, while host redirects and representation/cache headers are tested over real local HTTP/HTTPS. No ASSETS mocks or production test seams were added; remote TLS checks remain strict.

- **[2026-11-24 — agent-readable exports]**: Share one validated exported-page inventory between sitemap and agent-file generation. Reuse published Markdown from Next.js page props where available to preserve original instructions, diagrams, and citations; convert only rendered main content with Turndown/GFM for other pages. Emit canonical/title/description frontmatter, index.md variants, and a grouped llms.txt during build; advertise only generated indexable targets. Rationale: one published source of truth avoids content drift, while local build-time conversion avoids managed-conversion training signals or a new runtime service. Pin build-only turndown 7.2.5 (released 2026-11-04) and turndown-plugin-gfm 1.0.2 (2018); both are older than seven days and npm audit remains clean. Agent outputs are uncommitted out/ artifacts, previewed with make build/serve rather than Next dev.

- **[2026-11-24 — generated sitemap]**: Generate sitemap URLs from actual exported HTML and its canonical/robots metadata after every Next.js build, rather than maintaining a parallel route list. Reject inconsistent canonicals and exclude admin/internal assets/noindex pages. Rationale: newly published guides must be discoverable automatically, while error/search/preview URLs must not be advertised. Use parse5 7.3.0, already installed transitively and now explicitly pinned as a build dependency, rather than fragile HTML regex parsing. Keep deterministic public/out copies and omit unverifiable last-modified dates.

- **[2026-11-24 — SEO metadata]**: Use one shared Next.js Head component with explicit static page paths, content-derived descriptions, canonical apex URLs, social metadata, and escaped JSON-LD. Rationale: search engines and agents must receive accurate metadata in exported HTML without waiting for JavaScript, and client navigation must replace rather than duplicate tags. Use the V15 Sailing brand without claiming official class-association status or inventing article authors/dates. A 1200×630 crop of the supplied CRDC fleet photo provides a consistent social preview. No external service or dependency was added.
